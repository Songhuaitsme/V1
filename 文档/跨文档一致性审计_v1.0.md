## 2. 主流程的一致语义

```text
任务到达
  -> 按绝对最晚启动时间EDF排序
  -> 取下一个任务
  -> 根据原始arrival和SLA得到绝对启动窗口
  -> 对声明的节点/路径集合枚举窗口内全部时间网格
  -> 硬过滤JIT、带宽、CPU、绝对SLA和预测覆盖
  -> 若无候选：PendingUncommitted；不占资源、不算接受
  -> 若有候选：策略在完整可行集合中评级和选择
  -> ReservationManager在一致快照上原子提交CPU/BW
  -> EventEngine推进Reserved/Transmitting/Running/Completed
  -> MetricsLedger按完整执行区间核算元、MWh和最终绿电归因
```

“是否等待”不再是独立二元动作：

```text
active_wait = selected.compute_start - earliest_feasible_start
```

值大于0就是主动等待；等于0就是选择最早可行开始。

## 3. 已发现并在文档中解决的冲突

### C-01 完整窗口与30点采样冲突

原冲突：需求描述直接搜索窗口，旧实现却允许`WAIT_GAIN_MAX_LOOKAHEAD_SAMPLES=30`跳过中间时间点；旧文档也把时间采样写成正式参数。

当前统一规则：

- 正式模式对声明路径集合枚举全部对齐时间点；
- 实际槽数必须等于理论槽数；
- 采样/Top-K只能进入独立`approximate`实验；
- 近似实验必须报告遗漏率、代表性覆盖和相对完整集合的最优候选遗憾；
- 正式与近似模型、回放、结果不得混写。

影响位置：需求R-14、R-24；算法I-16；测试CAND-011、CAND-012、CAND-016至CAND-018。

### C-02 仿真时间注释与实际配置冲突

当前实际配置：

```text
TRAFFIC_DAY_DURATION_IN_SIM = 288
seconds_per_sim_unit = 86400 / 288 = 300秒
SCHEDULING_CYCLE = 0.005仿真单位 = 1.5秒
```

`config.py`旧注释写“120秒”和“4.8秒”，且使用了另一个日长度/周期数值，不能作为依据。文档已统一为从一个时间换算器派生秒、小时和仿真单位。

同一规则也适用于CPU工作量：`CPU×仿真时间单位`只可命名为`cpu_work_sim_units`；正式报告使用换算后的`cpu_work_cpu_hours`，主成本指标单位为元/CPU小时。`data_size_mb`固定为十进制MB，避免MB/MiB造成发送时间差异。

影响位置：需求R-03；算法I-15；测试UNIT-001至UNIT-003。

### C-03 成本名称与物理量纲冲突

当前旧实现的关键链路：

```text
BASELINE_ELECTRICITY_PRICE_YUAN_PER_MW
  -> 乘CPU_POWER_UNIT_MW
  -> 乘cpu_time_demand（CPU×仿真时长）
```

该链路缺少仿真时长到小时的转换；“元/MW”本身也是功率价格而非能量电价。因此旧绝对成本值只能视为内部指数，不能称为元。

当前`0.50~1.30`价格尺度还存在1000倍迁移风险：若它们是元/kWh，进入统一计费层必须乘1000成为`500~1300元/MWh`；若它们只是相对值，则只能命名`cost_index`。只改字段后缀会制造看似有单位、实际差1000倍的结果。

已冻结F-06口径：

```text
task_power_mw = cpu_demand × CPU_POWER_UNIT_MW
task_energy_mwh = ∫ task_power_mw dt_hours
economic_cost_yuan = ∫ tariff_yuan_per_mwh × task_power_mw dt_hours
```

无物理单位的优化信号必须命名`cost_index`。CPU拥塞加价与主经济成本分账。

影响位置：需求R-25、R-26；算法I-15；测试COST-001至COST-011。

### C-04 Pending重搜与完整窗口冲突

完整窗口、确定性资源日历和不可取消预约下，单纯推进当前时间不会创造新候选；已知释放已经包含在未来日历中。因此正式模式不得无变化逐周期重搜。

Pending仍被保留，用于表达“暂未承诺”以及兼容以下真实状态变化：

- 预约回滚释放容量；
- 节点/链路故障恢复；
- 容量明确增加；
- 后续阶段允许取消或重规划。

如果第一阶段没有配置这些事件，Pending任务只需接受到期检查，不重复做同一场搜索。采样分段扩大覆盖只能是近似实验理由。

### C-05 候选估计与最终账本冲突

候选生成时只能基于当前已知预约估计成本和绿能；之后到达的任务可能改变并发绿电分摊。文档已统一为：

- 预约时保存`estimated_*`；
- 完成时保存`realized_*`；
- 绿电最终按同节点同时间并发任务功率比例分摊；
- 完成修正进入事件奖励/累计回报，不静默篡改已消费回放。

外生电价且线性功率不受后续任务影响时，成本估计值与实现值应完全相等；绿电实现值仍可能因后续并发任务改变。

绿电还必须区分两个不可互换的分子：

- `task_attributed_green_energy_mwh`：最终按并发任务功率比例归因，跨任务可加；
- `candidate_marginal_green_energy_mwh`：系统加入候选前后的绿电使用差，属于反事实增量，不要求跨任务可加。

若绿电在加入任务前已经全部吸纳，后者为0，但前者仍可大于0。组合绿能目标可以同时使用覆盖率和吸纳增量，但实现与报告必须保留两个原始字段。

### C-06 截止边界与时间网格冲突

“绝对截止闭区间”不表示可以插入非调度网格时间。统一规则为：

```text
grid_first = ceil_to_global_cycle(decision_time + path_tx_duration)
grid_last = floor_to_global_cycle(absolute_latest_start)
```

枚举二者之间全部网格点。截止恰好对齐时包含截止；不对齐时，最后候选是截止前最后网格点。这样同时保持SLA闭边界和调度周期语义，并使理论槽数唯一可验证。

### C-07 可行候选与主动拒绝冲突

旧表述允许“系统策略拒绝”，但候选DQN动作只包含可行候选，并未说明Q值很低时能否拒绝。统一推荐规则为：第一阶段候选非空就必须选择，策略没有`Reject`或“继续Pending”动作；即时拒绝仅由字段非法、静态绝对不可承载和队列溢出等确定性规则产生。

这样最早基线、启发式和DQN使用相同接纳规则，成本改善不能来自选择性少接任务。若未来研究学习式接纳控制，应作为独立阶段并增加完成率/接纳率约束。

### C-08 “不无限重试”与不可重规划冲突

第一阶段预约不可取消、迁移或重规划，因此Reserved任务真实故障后不能再自动预约；统一为直接进入终态`Failed`，`MAX_FAILURE_RETRIES=0`。Pending由绝对启动截止终止，不按次数丢弃；原子提交版本冲突使用独立、有限的`commit_attempts`，达到上限后回Queued或按截止进入Expired。三种计数不得共用旧`retry_count`。

### C-09 DQN决策步数与物理时间冲突

同一调度周期可能包含多个零时间间隔的任务决策，任务完成修正又可能晚很多秒到达。如果每次决策固定乘gamma，改变批处理上限就会改变同一物理轨迹的回报。统一使用`gamma_per_second ** elapsed_seconds`；同一时刻决策折扣为1，时间推进和系统事件按实际秒数折扣。Replay必须保存决策时间、下一转移时间和经过秒数，事件缓冲中的每条奖励也必须保留自身时间戳；逐事件转移与带时间戳聚合必须等价。

### C-10 候选边际成本与最终任务成本冲突

外生线性电价下，候选带来的系统账单增量等于直接分给任务的能源成本。含绿电补贴/碳税的状态相关计费可能改变同节点所有任务的统一单价，此时两者不再相等。候选评级统一使用加入前后节点总账之差；最终任务报表按并发功率比例分摊节点实际任务账单。边际成本不要求可加，归因成本必须跨任务可加并且与预约顺序无关。

### C-11 排空accepted与结算全部arrived冲突

只排空Reserved/Running会把到达截止时仍在Queued/Pending的任务留作截尾，使完成率依赖评估结束时刻。正式评估改为三阶段：停止新到达后先让全部已到达任务完成接纳结算，再排空全部accepted。所有任务窗口有限，因此正式结果末尾应零非终态；安全上限触发必须判seed无效，不能静默汇总。

### C-12 排队、传输和主动等待重复计量

旧实现把从到达到候选开始的差称为queue delay后又加network delay，存在重复计量。统一分解为`decision-arrival`、`earliest_start-decision`和`selected-earliest`三项，三者之和严格等于启动时延。最早可行提前量已经包含JIT、网格和资源可用性，不再额外叠加network delay；无候选Expired任务没有active_wait。

### C-13 无效seed与选择性删除冲突

任一策略在某seed出现硬机制违规、安全上限或不完整结算时，该seed不能产生合法配对差。整个pair必须标记无效并使正式机制验收失败；不得只删除表现差的一侧、事后替换seed或静默跳过。修复后按原冻结seed集合重跑全部策略。

### C-14 业务场景覆盖与公开契约覆盖不等价

原测试规格虽然经过了主要成功/失败场景，但没有保证每个公开结果码都能唯一触发，也没有逐个约束服务副作用。例如资源版本变化、候选自身过期和事务异常分别应返回`CONFLICT/CANDIDATE_STALE/INTERNAL_ROLLBACK`；传输失败、执行失败和预约破坏都进入Failed，但终态原因不能合并。

统一增加R-47：固定状态转换表、候选/提交状态优先级、终态—原因映射、14个服务的读写边界以及三类输出schema。新增CONTRACT和SCHEMA测试族直接验证每条公开路径；端到端测试不再被当作接口契约的唯一证据。

### C-15 防除零默认值与指标语义冲突

旧实现中的`safe_ratio`和多处`max(denominator,1e-8)`能防止程序异常，却可能把“没有到达任务、没有已完成CPU小时、没有绿电机会、没有该SLA子群”伪装成有效0，或在基线为0时生成巨大相对百分比。程序不报错不等于指标有定义。

统一增加R-48和`MetricValue`：输入数值先做有限/正值域校验；合法但分母为0或样本为空时输出`NOT_APPLICABLE(null)`及原始分子/分母；非法运行输出`INVALID`；正式JSON/CSV禁止NaN/Infinity。只有全节点零利用率的CV等明确声明极限语义的指标使用固定约定。配对主指标任一侧非VALID时整个pair无效，不填0、不单侧删除。

### C-16 指标公式相同但聚合总体不同

逐任务覆盖率均值、按MWh加权的总体覆盖率，按循环采样的P95、按事件持续时间加权的P95，以及把所有任务跨seed池化、先每seed汇总再配对，都可能对同一日志给出不同结论。只写“平均/P95/覆盖率”不足以复现正式验收。

统一增加R-49：warmup排除、到达至最终结算构成核算区间；成本用总成本/总CPU小时；主任务覆盖按能量加权；系统消纳包含无任务时的闲置供给；资源利用按事件区间时长加权；任务百分位默认线性插值；每seed先汇总、seed等权配对；t/bootstrap方法及随机种子写入元数据并在正式结果前预注册。

### C-17 闭截止与同一时间戳到期顺序冲突

绝对最晚启动是闭边界，但若事件循环在资源释放和当前任务调度之前先执行到期检查，恰好能在截止时刻使用释放资源的任务会被错误Expired。同刻新提交任务若等到下一周期才进入Running/Transmitting，也会产生虚假等待和状态统计。

统一增加R-50和I-19：每个时间戳作为原子批次，依次积分、结束释放/结算、激活既有开始、注入到达/重激活、EDF逐任务提交、激活新提交即时开始、最后执行闭截止到期，并只生成一次批次后系统快照。重复`advance_to(t)`幂等；同刻决策折扣为1。

## 4. 七项已冻结业务选择

| ID | v1.0结论 | 后续版本若改变的影响 |
| --- | --- | --- |
| F-01 | Soft约束计算开始；偏好L、绝对1.2L | 若改约束完成，窗口需扣执行时长 |
| F-02 | `None`迁移为偏好L、绝对1.5L且线性迟到的`Flexible` | 若真正无截止，需系统级外部批处理边界 |
| F-03 | 固定预留带宽的流水线传输 | 若动态共享，旧预约完成时间会受新流量影响 |
| F-04 | 在线逐任务立即预约，按绝对期限EDF | 若联合选任务，动作空间与公平性模型都需重做 |
| F-05 | 绿电最终按并发任务功率比例归因 | 若用边际差直接归因，结果依赖预约顺序 |
| F-06 | 线性增量CPU功率，元/MWh×MW×小时计费 | 若采用异构总功耗，必须补节点功率曲线/PUE/分摊规则 |
| F-07 | 候选非空必须选择，不做学习式主动拒绝 | 若允许拒绝，需新增接纳控制动作、奖励和公平比较规则 |

这七项均已获得明确结论。奖励系数、DQN层数、学习率和候选路径K值属于实现/实验参数，不得反向改变已冻结业务语义。
