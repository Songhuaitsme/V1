# 分布式异构算力调度系统实施改造方案

版本：v1.0（需求基线）  
日期：2026-07-17  
依据：`需求规格说明_v1.0.md`、`需求追踪矩阵_v1.0.md`、`调度算法设计_v1.0.md`、`领域对象与接口契约_v1.0.md`、`验收测试规格_v1.0.md`、`关键业务决策论证_v1.0.md`  
状态：实施路线基线；运行代码修改尚未授权  

## 0. 文档目的

本文把已经形成的需求、算法和接口契约转换为可执行的代码改造顺序，回答四个问题：

1. 现有文件分别保留什么、拆出什么、替换什么；
2. 已冻结业务语义如何约束实现顺序；
3. 每个工作包用什么证据证明完成；
4. 如何避免旧模型、旧指标和新机制混用后产生不可解释结果。

F-01至F-07和S-01至S-15已经冻结，权威结论见`需求确认记录_v1.0.md`。本文只规定获得代码授权后的实现顺序、边界和证据，不构成运行代码修改授权。

## 1. 当前实现结论

当前系统已经具备任务生成、拓扑、价格/绿电画像、固定动作DQN、训练循环和冻结策略评估等原型能力，但还不能把现有结果解释为v1.0机制的正式验证。

| 层次 | 当前实现 | v1.0目标 | 主要风险 |
| --- | --- | --- | --- |
| 时间与单位 | 仿真时间、秒、小时及价格量纲在多个模块中隐式换算 | 所有跨边界值使用显式单位和统一转换 | 传输、SLA、成本可能相差固定倍率 |
| 资源预约 | 任意区间重叠的预约直接求和，CPU/BW在策略成功后写入 | 半开区间真实并发峰值检查，一致快照原子提交 | 虚假拒绝、容量漏检、部分提交 |
| 任务状态 | 主要使用队列、`started`和调度成功状态 | 显式生命周期及终态原因 | Reserved被误记为Completed |
| 传输 | 多跳可能重复计算完整数据串行化，带宽区间与计算区间混用 | 固定预留带宽、流水线、JIT区间 | 传输时长和链路占用都不可信 |
| 候选 | 时间可能最多采样30点，DQN只看到节点+WAIT | 声明路径集合×完整启动网格的可提交候选 | 正式模式漏掉最优时间或路径 |
| 队列 | retry参与优先级，多种失败合并为drop | 绝对期限优先、Pending事件重搜、原因分账 | 饥饿、重复搜索、状态统计失真 |
| 计费与绿能 | 开始时刻快照，经济价格、绿电和拥塞塑形混合 | 完整区间积分，边际估计与最终归因分离 | 元/MWh、MW、MWh混用，目标重复计权 |
| 学习 | 固定长度动作和整数动作回放 | 共享候选Q函数和可变下一候选集合 | Agent选择后环境再次替换方案 |
| 评估 | 调度成功即记成功，任务到达结束后不排空 | 到达、接纳结算、执行排空三阶段 | 完成率和单位完成成本被高估 |

因此，优先修复顺序必须是基础语义和机制，再接确定性策略，最后接DQN与奖励；不得从调整权重或延长训练开始。

## 2. 实施约束

### 2.1 权威顺序

出现冲突时按以下顺序处理：

```text
需求确认记录_v1.0
  > 需求规格
  > 接口契约
  > 调度算法设计
  > 验收测试规格
  > 当前代码和旧测试行为
```

当前代码不能反向定义需求。旧测试若锁定逐周期WAIT、retry丢弃或预约即成功，应先标为旧行为证据，再由新需求测试替代。

### 2.2 迁移原则

- 每个工作包只改变一个可解释层次，不同时修改物理机制、奖励和网络结构；
- 新机制使用独立schema版本，禁止把旧字段静默解释为新字段；
- 所有资源区间统一为半开区间`[start,end)`；
- 正式`complete`候选与`approximate`候选从入口、元数据到结果目录完全隔离；
- 旧引擎只可用于诊断对照，不得产生v1.0正式baseline；
- 每个阶段先通过手算和小拓扑测试，再运行随机压力测试；
- 任一硬门槛失败时停止进入下一阶段，不能用平均奖励改善抵消。

### 2.3 已冻结F项的实现影响

F-01至F-07均已确认，以下接口语义不再由实现者选择：

| F项 | 冻结后影响的主要实现 |
| --- | --- |
| F-01 | `TaskSpec`使用start边界、SLA过滤、Soft迟到指标 |
| F-02 | SLA枚举、Flexible `L/1.5L`窗口、旧`None`迁移及通用偏好迟到字段 |
| F-03 | `TransmissionModel`签名、JIT区间、链路日历 |
| F-04 | 队列排序键、逐任务提交时机、公平性语义 |
| F-05 | 能量账本、最终绿电归因和顺序不变性测试 |
| F-06 | 功率模型、价格配置迁移、经济计费公式 |
| F-07 | 动作schema、Pending入口、确定性拒绝原因 |

## 3. 目标模块边界

建议按以下职责拆分。目录名可以在实施时调整，但职责和副作用边界不得合并回单个`env.step()`。

| 建议模块 | 唯一职责 | 从现有代码迁入 | 明确禁止 |
| --- | --- | --- | --- |
| `domain/units.py` | 仿真时间、秒、小时、数据、能量、价格换算 | `task_manager.py`的周期秒换算 | 读取策略或资源状态 |
| `domain/models.py` | `TaskSpec/Runtime/Candidate/Reservation/DecisionRecord` | 现有任务dict和allocation字段 | 执行调度副作用 |
| `domain/sla.py` | SLA派生边界、硬过滤和迟到比例 | `network_env.py`中的分支判断 | 读取Q值或奖励权重 |
| `scheduler/resource_calendar.py` | CPU和链路区间峰值、快照、原子提交 | `network_env.py`预约索引 | 计算成本、选择候选 |
| `scheduler/transmission.py` | 固定带宽传输时长与JIT区间 | `topology_manager.py`传输公式 | 动态改变已预约任务速率 |
| `scheduler/path_provider.py` | 声明候选路径集合 | `topology_manager.py.find_path` | 根据策略分数删路径 |
| `scheduler/candidate_generator.py` | 完整/近似候选生成和硬过滤 | `_candidate_times_for_task`、`evaluate_schedule_candidates` | 提交资源、替策略选候选 |
| `scheduler/queue_manager.py` | 排队、Pending、到期和重激活 | `task_manager.calculate_priority`、训练队列逻辑 | 把retry次数作为业务优先级 |
| `scheduler/policies.py` | 确定性策略及统一选择接口 | 当前人工候选评分的一部分 | 修改候选和资源日历 |
| `simulation/event_engine.py` | 生命周期、同刻事件顺序、正常释放 | `update_active_tasks` | 生成新候选或重写历史 |
| `accounting/forecast.py` | 外生价格/绿电预测快照 | `pricing_manager.py`的时间画像 | 读取未来任务 |
| `accounting/ledger.py` | 区间成本、绿能、负载和状态账本 | `PricingManager`与评估指标 | 影响调度可行性 |
| `agents/candidate_dqn.py` | `Q(global,candidate)`与选择 | `dqn_agent.py` | 自己构造或替换候选 |
| `agents/replay.py` | 可变候选集合、时间戳奖励回放 | `PrioritizedReplayBuffer` | 丢失下一候选集合或时间戳 |
| `evaluation/runner.py` | 冻结轨迹、三阶段结算、配对统计 | `evaluate.py` | 单侧删seed、预约即记完成 |

### 3.1 现有文件的去留

| 现有文件 | 实施策略 |
| --- | --- |
| `config.py` | 保留为入口配置；改成显式单位、模式和schema版本，旧键经过受控迁移后弃用 |
| `network_env.py` | 保留兼容外观，逐步缩减为服务编排适配器；候选、预约、SLA、账本不得继续内嵌 |
| `topology_manager.py` | 保留拓扑和路径能力；传输物理量移入独立模型，路径静态容量必须始终检查 |
| `pricing_manager.py` | 拆成预测、功率、经济计费与策略塑形；不再返回含义混合的单一动态价格 |
| `task_manager.py` | 保留任务轨迹生成；任务schema、队列排序和运行状态移出 |
| `dqn_agent.py` | 旧固定动作模型标记legacy；新候选模型使用独立模型schema，禁止静默加载旧权重 |
| `train.py` | 变成训练编排器；不直接写CPU/BW日历，不在同一循环重复实现队列和状态机 |
| `evaluate.py` | 变成评估入口；核心逻辑下沉到可单测runner和ledger |
| `test_cpu_occupancy_model.py` | 旧WAIT相关测试分类为legacy/replace；通用CPU固定性测试保留 |
| `test_evaluate.py`、`test_pricing_ablation.py` | 保留适用断言；预约即成功、快照计费等断言必须按新口径改写 |

### 4.2 每个工作包的退出标准

工作包只有同时满足下列条件才算完成：

1. 所覆盖需求均有具体测试ID；
2. 正常测试和至少一个针对关键硬约束的故障注入测试通过；
3. 产生可审计输出，而不是只返回布尔值；
4. 未覆盖需求的行为保持不变，或变更已在记录中声明；
5. 新旧schema不会被静默混读；
6. 代码、配置、测试和文档引用同一需求ID；
7. 复核工作区差异，确认没有顺带调整奖励权重或训练参数。

## 5. 配置迁移方案

### 5.1 必须新增的元配置

```text
REQUIREMENTS_VERSION = "0.3"
TASK_SCHEMA_VERSION
CANDIDATE_SCHEMA_VERSION
METRIC_SCHEMA_VERSION
MODEL_SCHEMA_VERSION
SCHEDULER_ENGINE = "legacy" | "v03"
CANDIDATE_MODE = "complete" | "approximate"
TARIFF_MODE = "exogenous" | "green_carbon_billing"
SIM_SECONDS_PER_UNIT = 300.0
GAMMA_PER_SECOND
```

`legacy`只允许生成诊断结果；正式结果必须为`SCHEDULER_ENGINE=v03`和`CANDIDATE_MODE=complete`。

### 5.2 现有配置映射

| 现有键 | 目标键/处理 | 迁移规则 | 依赖 |
| --- | --- | --- | --- |
| `TRAFFIC_DAY_DURATION_IN_SIM` | 保留 | 以`SIM_SECONDS_PER_UNIT`验证一天对应86400秒；修正旧注释 | 无 |
| `GLOBAL_TIME_STEP_DURATION`、`SCHEDULING_CYCLE` | 只保留一个调度网格真源 | 若两者不等则启动失败；候选网格锚定仿真原点0 | 无 |
| `TASK_DATA_SIZE_RANGE` | `TASK_DATA_SIZE_MB_RANGE` | 数值按十进制MB解释并写入元数据 | 无 |
| `TASK_BW_DEMAND` | `TASK_BANDWIDTH_DEMAND_MBPS_RANGE` | 明确Mbps，不改变数值 | F-03 |
| `TASK_LATENCY_LIMIT_RANGE` | Soft/Flexible迁移为`PREFERRED_START_LIMIT_RANGE`并派生latest | Soft派生`1.2L`、Flexible派生`1.5L`；Hard使用独立绝对限制 | F-01、F-02 |
| `MAX_RETRIES*` | `MAX_COMMIT_ATTEMPTS`；真实失败重试固定0 | Pending不受计数式丢弃；旧值不自动迁移 | F-07相关 |
| `RETRY_PRIORITY_WEIGHT` | 删除 | retry/pending次数不得进入业务排序 | F-04 |
| `WAIT_GAIN_LOOKAHEAD_CYCLES` | 从正式候选配置删除 | 可迁到近似实验命名空间 | 已确认S-14 |
| `WAIT_GAIN_MAX_LOOKAHEAD_SAMPLES` | `APPROX_MAX_TIME_SAMPLES` | 只在`approximate`模式有效；正式模式设置即报错 | 已确认S-14 |
| `WAIT_GAIN_*_WEIGHT` | 迁入legacy或确定性启发式配置 | 不作为候选物理字段，不决定可行性 | S-03 |
| `WAIT_PENALTY_PARAMS` | 退役或保留legacy | 主动等待价值由候选差和实现事件产生，不用独立WAIT动作惩罚代替 | F-07 |
| Soft/Flexible迟到权重 | `SOFT_TARDINESS_WEIGHT`、`FLEXIBLE_TARDINESS_WEIGHT` | 分别作用于同一`preferred_start_tardiness_ratio`；数值由pilot/消融冻结 | F-01、F-02 |
| `BASELINE_ELECTRICITY_PRICE_YUAN_PER_MW` | `BASE_TARIFF_YUAN_PER_MWH` | 若原0.50至1.30为元/kWh，显式乘1000；若为相对量则转`cost_index` | F-06 |
| `CPU_POWER_UNIT_MW` | `INCREMENTAL_CPU_POWER_MW_PER_CPU` | 在线性模型中明确为每CPU增量功率 | F-06 |
| `PRICE_ALPHA/BETA` | `CONGESTION_SHAPING_*` | 不再进入外生经济成本账 | S-09 |
| `GREEN_SUBSIDY_RATE/CARBON_TAX_RATE` | 状态相关计费配置 | 与外生价格实验分开，不得两种口径共用结果列 | S-09 |
| `GAMMA` | 迁移为`GAMMA_PER_SECOND` | 先声明旧GAMMA对应的物理时间基准，再换算；不能直接改名 | R-44 |
| `INPUT_DIM/NODE_NUM` | legacy专用 | 新模型从特征schema和候选编码器推导维度 | R-22、R-23 |
| `MAX_TASKS_PER_CYCLE` | 保留 | 未轮到的合法任务继续Queued，不记drop | S-12 |
| `MAX_QUEUE_LENGTH` | 保留 | 只控制真实排队容量；溢出使用独立终态原因 | S-12 |

### 5.3 禁止的兼容行为

- 不得把旧`None`整数编码直接映射成`Flexible`而不生成偏好`L`和绝对窗口`1.5L`；
- 不得用变量重命名伪装价格量纲转换；
- 不得让旧模型输出维度“碰巧相同”就加载到新候选模型；
- 不得在`complete`模式静默启用时间采样或Top-K；
- 不得把旧`success`列重命名为`completed`；
- 不得用默认值填充缺失schema版本后继续生成正式结果。

## 6. 数据、模型和结果兼容性

### 6.1 模型

固定节点+WAIT模型与共享候选Q模型语义不兼容。新加载器必须校验：

```text
requirements_version = "1.0"
algorithm_version = "1.0"
task_schema_version = "1.0"
candidate_schema_version = "1.0"
model_schema_version = "1.0"
metric_schema_version = "1.0"
aggregation_schema_version = "1.0"
feature_schema_hash
```

任一缺失或不一致时返回明确不兼容错误。旧权重可作为legacy诊断资产保留，但不能“迁移”成新模型性能起点。

### 6.2 任务轨迹

旧任务轨迹可以通过显式适配器读取，但适配器必须：

- 保存原始字段和值；
- 记录采用的SLA迁移规则；
- 为每个任务生成稳定`task_id`；
- 拒绝单位或SLA边界无法判定的记录；
- 输出迁移报告和新trace哈希。

正式配对实验中的所有策略必须读取同一迁移后trace哈希。

### 6.3 结果

旧`evaluation/baseline`只能标记为`legacy-diagnostic`。新结果目录至少按以下字段隔离：

```text
requirements_version / scheduler_engine / candidate_mode /
tariff_mode / model_schema_version / experiment_id
```

旧完成率、成本和绿电列不得与v1.0列拼接计算均值或置信区间。

| G-5 账本可信 | E-08、E-09通过，任务分账之和与系统账一致 | 不优化成本/绿能权重 |
| G-6 评估可信 | E-11至E-14通过；正式末尾零非终态 | 不生成baseline |
| G-7 学习接口可信 | E-10通过；候选置换、可变集合、折扣等价 | 只发布确定性baseline |
| G-8 机制pilot | 至少10个配对seed，硬门槛全0并完成功效分析 | 调整实验规模或机制，不宣称正式收益 |
| G-9 正式实验 | 预注册种子、阈值和元数据齐全，全部策略有效 | 整个无效seed pair失败，不换seed |

## 8. 双轨验证与回退

实施期间可以保留`legacy`和`v03`双轨入口，但目的仅是定位差异，不是要求新机制复现旧错误。

每次切换至少保存：

- 相同任务和外生轨迹哈希；
- 两个引擎的状态转移日志；
- 候选集合摘要和资源日历快照；
- 差异首次出现的任务、事件和需求ID；
- 是否属于预期语义变更。

回退规则：

1. 工作包内部失败时只回退该工作包入口，不回写已通过的领域schema；
2. 回退到legacy后结果自动降级为诊断，不能继续v1.0正式流水线；
3. 旧配置、旧模型和旧CSV始终只读保存；
4. 不通过删除失败任务、缩短候选窗口、减少路径集合或替换seed使测试恢复绿色。

## 10. 获得确认后的首批实施顺序

获得代码实施授权后，第一批只完成WP-1，不同时触碰候选评分或DQN：

1. 读取已冻结的F-01至F-07、S-01至S-15和v1.0任务字段schema；
2. 新增统一时间、数据和价格换算；
3. 把任务不可变业务字段与运行状态分离；
4. 为旧任务dict提供显式迁移适配器；
5. 增加E-01及SLA字段边界测试；
6. 在不改变训练入口行为的条件下完成影子读取；
7. 复核差异后再进入WP-2。

第一批完成不代表v1.0调度机制已完成，也不应重新训练模型。最早允许运行确定性v1.0机制实验的节点是G-6通过之后；最早允许训练新候选DQN的节点是G-7接口测试通过之后。
