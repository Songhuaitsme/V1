# 当前系统详细说明（v1.0实现态）

版本：v1.0  
日期：2026-07-18

## 1. 系统解决的问题

系统接收带CPU、执行时长、数据量、带宽需求和启动SLA的在线任务，在多个计算节点、候选路径和未来时间槽之间选择一个可直接原子提交的预约。优化目标包括物理经济成本、绿能覆盖/吸纳、负载余量和Soft/Flexible偏好迟到，同时保证CPU、带宽和绝对启动SLA零违规。

正式调度链路为：

```text
任务到达
  -> 字段/SLA校验与确定性接纳检查
  -> 按固定队列键排序
  -> 节点 × 路径 × 完整预测时间网格枚举
  -> 物理/SLA/预测覆盖过滤
  -> 策略或Candidate-DQN从非空候选中选一个
  -> CPU与全路径带宽原子预约
  -> JIT传输/计算/完成事件推进
  -> 完成后物理能耗、成本和绿能归因
  -> 正式指标、配对统计和不变量审计
```

## 2. 任务模型与SLA

正式任务使用不可变`TaskSpec`，运行状态单独保存在`TaskRuntime`。关键字段为：

- `arrival_time_sim`：到达时刻；
- `cpu_demand`：计算期间固定CPU占用；
- `execution_duration_sim`：固定执行时长；
- `data_size_mb`：十进制MB；
- `bandwidth_demand_mbps`：JIT传输固定预留带宽；
- `preferred_start_limit_sim`：Soft/Flexible偏好启动时限；
- `latest_start_limit_sim`：绝对最晚启动时限。

SLA判断点是数据到达计算节点、具备开算条件的`compute_start`。执行时长不进入启动SLA。

| 类型 | 偏好启动 | 绝对最晚启动 | 偏好迟到比例 |
| --- | --- | --- | --- |
| Hard | 不适用 | `L` | 报告NOT_APPLICABLE；模型输入0并带适用性标志 |
| Soft | `L` | `1.2L` | `clip((start_delay-L)/(0.2L),0,1)` |
| Flexible | `L` | `1.5L` | `clip((start_delay-L)/(0.5L),0,1)` |

历史`None`只允许经迁移器转换为Flexible；旧`latency_limit`成为`L`。没有有效正数`L`时迁移失败，不能猜测默认期限。

## 3. 任务到达后的选择顺序

任务首先接受确定性规则检查：字段非法、CPU/路径静态永远不可承载、或调度队列容量溢出时，分别记录明确拒绝原因。通过检查的任务进入Queued。

每一调度批次严格按以下键升序处理：

1. 绝对最晚计算开始时刻；
2. SLA类型：Hard、Soft、Flexible；
3. Soft/Flexible绝对偏好开始时刻；Hard该项不适用；
4. 到达时刻；
5. `task_id`。

`retry_count`、Q值、奖励和策略偏好均不能改变任务处理顺序。同一批次逐任务在线提交，后一个任务一定能看到前一个任务刚写入的CPU/BW预约。

## 4. 系统如何确定是否等待

v1.0不再把WAIT设计为独立动作。是否等待由“选中的候选时间”自然表达：

- 候选集合非空：策略必须选择一个候选，不能学习式Reject，也不能继续Pending；
- 若选中候选是当前最早可行时间，`active_wait=0`；
- 若选中更晚的未来候选，系统立即原子预约该未来时段，`active_wait=selected_start-earliest_feasible_start`；
- 完整窗口当前没有任何可提交候选且尚未到绝对期限：任务进入`PendingUncommitted`，它不占资源、也不算accepted；
- Pending只在CPU/BW释放、容量变化或预测覆盖扩展等物理事件后重搜；普通时钟推进不重复搜索；
- 到绝对截止边界时先给任务最后一次闭边界调度机会，仍为空才转为Expired。

因此，v1.0区分两种“等待”：策略主动选择未来预约，以及因当前全窗口无解而处于未承诺Pending。两者在状态、资源占用和指标中完全分开。

## 5. 如何确定预测窗口

窗口始终从原始到达时刻定义，不因Pending或冲突重试而重置：

```text
absolute_latest_start = arrival_time + latest_start_limit
```

Hard搜索至`arrival+L`，Soft搜索至`arrival+1.2L`，Flexible搜索至`arrival+1.5L`。预测还必须覆盖候选的完整计算区间至`compute_end`；范围外请求明确返回`FORECAST_NOT_COVERED`，不使用起点值外推。

第一阶段采用完美外生预测：未来电价和绿电轨迹可查询，但尚未到达的未来任务不可见。预测对象不可变并带版本号。

## 6. 如何在窗口内寻找节点、路径与时间

正式`complete`模式对每个任务执行以下过程：

1. 遍历所有声明计算节点；
2. 对源节点到目标节点取固定、确定的最多K条候选路径；当前正式默认`K=1`；
3. 按任务固定带宽计算流水线传输时长：整份数据序列化只计算一次，逐跳传播时延累加；
4. 计算JIT最早开始：`earliest_jit = decision_time + transmission_duration`；
5. 将最早时刻向上对齐全局调度网格；
6. 从该网格点完整枚举到任务绝对最晚启动边界；
7. 对每个节点-路径-时间候选检查：预测覆盖、CPU区间真实并发峰值、路径每条边带宽峰值、JIT可行性和启动SLA；
8. 为每个保留候选计算成本、绿能、容量余量、迟到和延迟分解；
9. 候选携带快照版本，可直接转换成原子`ReservationRequest`。

正式模式不采样、不按人工总分预先Top-K。另有显式`approximate`实验模式，它保留最早、最低成本、最高绿能、最均衡及Pareto非支配候选，并报告遗漏率和相对完整集合遗憾；该模式不得与正式结果混合。

## 7. 候选评级依据

### 7.1 硬过滤

评级前先删除所有物理或SLA非法候选。再高的奖励或Q值也无法恢复非法候选，因此正式约束违规目标为0，而不是通过惩罚允许少量违规。

### 7.2 原始候选指标

每个候选包含：

- 完整执行区间边际系统经济成本（元）；
- 任务绿能覆盖率；
- 边际绿能吸纳增量（MWh）；
- 节点和路径投影利用率；
- 容量余量；
- `preferred_start_tardiness_ratio`；
- queue delay、最早可行提前量、active wait、reservation lead和start delay。

### 7.3 确定性策略

系统内置：

- `earliest_feasible`：最早计算开始；
- `lowest_cost`：最低边际系统成本；
- `highest_green`：最高绿能覆盖，再比较吸纳增量；
- `equal_weight`：成本和绿能等权的固定尺度综合分，再加入负载余量和迟到项。

等权目标的核心形式为：

```text
score = w_cost * normalized_cost
      + w_green * (0.5 * green_coverage + 0.5 * normalized_absorption)
      + w_balance * capacity_margin
      - w_tardy(type) * preferred_start_tardiness_ratio
```

成本、吸纳使用冻结配置尺度，不从当前测试候选集合动态求min/max。Soft和Flexible迟到系数独立配置；当前默认值为pilot占位参数0，不改变可行性边界。

### 7.4 Candidate-DQN

DQN不是输出固定节点动作，而是对每个可行候选独立计算`Q(global_state,candidate)`。它使用共享候选编码器，支持可变候选数量；即使所有Q值为负，也选择最大Q候选。探索只用于训练，正式评估探索率为0。

模型输入含18维候选特征和18维全局状态。回放保存被选候选、下一可行候选集合、物理时间戳和事件奖励。Double-DQN目标只对下一可行集合求值，折扣为`gamma_per_second ** elapsed_seconds`。

## 8. 原子预约和事件生命周期

远程候选使用：

```text
传输区间 [transmission_start, compute_start)
计算区间 [compute_start, compute_end)
```

CPU和路径所有链路在同一快照版本上重新检查并原子写入。CPU失败、任一链路失败、版本冲突或注入异常都不会留下部分预约。技术性版本冲突允许有限次数重新取快照；真实故障不作为业务重试。

生命周期为：

```text
Arrived -> Queued -> Reserved -> Transmitting -> Running -> Completed
                    \-> Running -> Completed              （本地任务）
Queued -> PendingUncommitted -> Queued/Expired
Arrived -> Rejected
Reserved/Transmitting/Running -> Failed
```

只有Completed算成功并进入最终实现账本。预约成功不等于完成。完成事件释放CPU；JIT传输结束后带宽立即释放。相同时间戳按结束/释放优先、既有开始、到达/重激活、逐任务提交、新提交即时开始、闭截止到期、批次指标快照的顺序处理。

## 9. 成本、能量和绿能核算

所有核算对完整物理时间区间分段积分，并显式把仿真时间转换为小时：

```text
energy_mwh = power_mw * duration_hours
economic_cost_yuan = Σ energy_mwh(slot) * tariff_yuan_per_mwh(slot)
```

候选阶段记录边际系统反事实估计；完成阶段记录最终任务归因，两者不能混成同一字段。最终绿能按同节点同时间的任务功率比例无顺序分摊，总归因不超过系统可用绿能。系统绿能吸纳率还包含正式评估区间内的空闲绿能分母。

## 10. 正式评估与审计

正式评估分三阶段：

1. 接收截止前到达任务并推进物理事件；
2. 停止新到达，结算所有Queued/Pending为Reserved、Rejected或Expired；
3. 排空所有已接纳预约至Completed或Failed。

输出包含逐任务、逐决策、逐seed和聚合记录。未定义指标使用`null + status`，不使用epsilon伪造分母，不允许NaN/Infinity。主动等待记录选中候选、最早反事实、收益向量、条件均值/P95和正收益率；没有主动等待任务时条件指标为NOT_APPLICABLE。

正式比较使用相同seed配对、样本标准差`ddof=1`、配对t区间或预注册bootstrap。少于10个种子只标记DIAGNOSTIC_ONLY。每个事件批次末运行物理/状态不变量检查；任何违规使正式运行失败关闭。

## 11. 当前默认值和实验边界

- 默认调度引擎：v1；
- 正式候选模式：complete；
- 正式默认确定性策略：earliest_feasible；
- 候选路径数：K=1；
- 成本/绿能主权重：0.5/0.5；
- 负载次权重：0.1；
- Candidate-DQN隐藏宽度：128；
- Soft/Flexible迟到权重、学习率和正式样本量仍由pilot/消融确定；
- 旧baseline未重算，不能用于宣称v1.0正式效果。

## 13. 训练运行保障

正式完整候选仍按声明节点、路径和完整时间网格遍历，但调度与DQN已改为流式分块处理，不再保留整张候选对象/特征矩阵。训练回放保存可重建下一候选集的决策上下文，随机小批量采样后按同一快照重新流式计算Double-DQN目标。epsilon和目标网络更新均以成功梯度更新次数为时钟，不按空调度周期推进。

训练入口在启动前报告任务数、SLA构成、理论候选槽总数和单任务最大槽数；超过安全线必须显式确认。检查点包含仿真现场、事件堆、预约日历、回放、优化器和Python/NumPy/PyTorch随机数状态，可从非终态现场继续。当前成本尺度及Soft/Flexible迟到权重仍是pilot占位参数，默认阻止长训练；操作顺序见`训练与效果评估操作指南_v1.0.md`。源码分类导航见仓库根目录`README.md`。
