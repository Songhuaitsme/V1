# 分布式异构算力调度系统公式与量纲审计

版本：v1.0  
日期：2026-07-17  
范围：时间、网格、传输、SLA、工作量、功率、能量、成本、绿电、折扣、时延和派生指标  
状态：v1.0公式基线审计；不证明当前运行代码已经实现这些公式  

## 1. 审计方法

本审计独立重算需求规格、算法设计、接口契约和验收测试中的核心公式，检查：

1. 等式两侧单位是否一致；
2. 闭/开边界和网格对齐是否唯一；
3. 比率分母为0时是否有明确语义；
4. 分项之和是否满足守恒；
5. 同一量在不同文档中是否同名同义；
6. 示例数值是否能由公式复现。

所有十进制手算使用高精度Decimal；没有读取或修改运行状态。

## 3. 时间与网格

### 3.1 配置派生

```text
seconds_per_sim_unit = 86400 / 288 = 300秒/sim-unit
cycle_seconds = 0.005 × 300 = 1.5秒
```

量纲：

```text
sim-unit × second/sim-unit = second
```

结论：当前配置旧注释中的120秒或4.8秒不能成立，应由统一转换器派生，不再手写第二套常量。

### 3.2 整数tick

给定决策100.5秒、远程传输8.005秒、周期1.5秒、绝对截止123秒：

```text
earliest_jit = 108.505秒
first_tick = ceil(108.505 / 1.5) = 73
last_tick = floor(123 / 1.5) = 82
slot_count = 82 - 73 + 1 = 10
```

完整网格：

```text
109.5, 111.0, 112.5, 114.0, 115.5,
117.0, 118.5, 120.0, 121.5, 123.0
```

截止123恰好对齐，必须包含；124.5越界。实现使用tick乘周期，不用`time += cycle`累积浮点误差。

## 4. 传输与JIT

十进制100MB等于800Mb：

```text
T_data = 800Mb / 100Mb/s = 8秒
T_prop = 1000km / 200000km/s = 0.005秒
T_tx = 8.005秒
T_tx_sim = 8.005 / 300 = 0.026683333333...仿真单位
```

量纲均正确。流水线模型只串行化一次完整数据，逐跳只累加传播；每条边在统一JIT区间固定预约任务带宽。这是第一阶段的简化资源承诺，不等于动态流量共享。

若计算开始112.5秒：

```text
transmission = [104.495,112.5)
compute = [112.5,compute_end)
```

带宽在112.5释放，CPU在112.5开始；半开区间不会重复占用边界。

## 5. SLA与时延

Soft偏好限制20秒、绝对限制24秒、启动时延22.5秒：

```text
preferred_start_tardiness_ratio = (22.5 - 20) / (0.2 × 20) = 0.625
```

公式要求`L>0`，因此新增字段校验；不能用ε把`L=0`改造成极端迟到值。

Flexible偏好限制20秒、绝对限制30秒：

```text
start_delay = 25秒:
preferred_start_tardiness_ratio = (25 - 20) / (0.5 × 20) = 0.5

start_delay = 30秒:
preferred_start_tardiness_ratio = (30 - 20) / (0.5 × 20) = 1

start_delay > 30秒:
absolute start SLA infeasible
```

Soft和Flexible使用同一字段与通用分母`latest_start_limit-preferred_start_limit`，但分别使用0.2L和0.5L迟到区间。

到达99、决策100.5、最早可行109.5、选择112.5：

```text
scheduler_queue_delay = 100.5 - 99 = 1.5秒
earliest_feasibility_lead = 109.5 - 100.5 = 9秒
active_wait = 112.5 - 109.5 = 3秒
start_delay = 1.5 + 9 + 3 = 13.5秒
            = 112.5 - 99
```

最早可行提前量已经包含JIT、网格和资源日历；再加`network_delay`会重复计量。

## 6. CPU工作量、功率、能量和成本

### 6.1 CPU工作量

CPU=100、执行12仿真单位：

```text
cpu_work_sim_units = 100 × 12 = 1200 CPU·sim-unit
execution_hours = 12 × 300 / 3600 = 1小时
cpu_work_cpu_hours = 100 × 1 = 100 CPU小时
```

两种工作量数值和单位不同，不能共用旧`cpu_time`列。

### 6.2 任务能量和外生价格

CPU=4、每CPU增量功率0.01MW、执行60秒：

```text
task_power = 4 × 0.01 = 0.04MW
task_energy = 0.04 × 60/3600
            = 0.0006666666667MWh
```

在1200、900、600元/MWh下：

```text
cost = 0.80元、0.60元、0.40元
```

这些值与端到端算例一致。若原始输入为1元/kWh，必须先转换为1000元/MWh；只改字段后缀会造成1000倍错误。

### 6.3 状态相关账单

```text
candidate marginal cost = bill(with) - bill(without)
task attributed cost = ∫ node_bill_rate × task_power/total_task_power × dt
```

前者是反事实边际量，不要求多个候选相加；后者是最终分账，所有任务之和必须等于节点任务账单。`node_bill_rate`是元/小时率，乘功率占比和小时得到元，量纲成立。

## 7. 绿电守恒

绿电6MW，任务A/B功率4/6MW：

```text
coverage_ratio = 6/(4+6) = 0.6
A attributed green = 4×0.6 = 2.4MW
B attributed green = 6×0.6 = 3.6MW
sum = 6MW
```

交换任务顺序不改变结果。对时间积分后同样满足MWh守恒。

需要继续区分：

- `candidate_marginal_green_energy_mwh`：加入候选使系统多吸纳多少，不可加；
- `task_attributed_green_energy_mwh`：最终公平归因多少，可加；
- `green_coverage`：任务归因绿电/任务能量；
- `green_absorption_delta`：系统吸纳率的反事实变化。

系统绿电供给为0时，吸纳率没有定义，不能用ε报告有效0。候选选择可把该维度设为中性0，但必须同时携带`green_opportunity=false`。

## 8. 候选评级

成本分量统一命名为：

```text
cost_score = clip(
    (reference_marginal_cost - candidate_marginal_system_cost_yuan)
    / cost_scale,
    -1, 1
)
```

此前正文公式使用`reference_marginal_cost`、说明文字使用`reference_cost`，现已统一。`cost_scale>0`。

绿电分量：

```text
normalized_green_coverage = green_coverage
normalized_absorption_delta =
    clip(green_absorption_delta / absorption_delta_scale, 0, 1)
```

`absorption_delta_scale>0`，正式结果前冻结；默认1表示直接使用吸纳率变化。测试集不得参与尺度选择。

## 9. 连续时间折扣

设`gamma_per_second=0.99`，5秒发生奖励2，10秒bootstrap Q=3：

聚合表示：

```text
2×0.99^5 + 3×0.99^10 = 4.61512632482641347003
```

逐事件表示：

```text
0.99^5 × (2 + 0.99^5×3)
= 4.61512632482641347003
```

差为0。同一时刻的零时长决策折扣为1；把轨迹拆成更多零时长决策不会改变回报。`gamma_per_second`必须满足`0<gamma<=1`，避免`0^0`和增长型折扣。

## 10. 零分母与空样本

新增R-48后，以下结果不再用`safe_ratio(...,default=0)`或`max(ε,denominator)`伪造：

| 场景 | 正确输出 |
| --- | --- |
| Arrived=0 | 接纳率/完成率NOT_APPLICABLE |
| Reserved_ever=0 | 预约可靠率NOT_APPLICABLE |
| completed CPU hours=0 | 元/完成CPU小时NOT_APPLICABLE，总成本保留 |
| 某SLA类型count=0 | 该类型比率/分位数NOT_APPLICABLE |
| green supply=0 | 系统消纳率NOT_APPLICABLE |
| 正值型baseline metric<=0 | 相对百分比NOT_APPLICABLE，绝对差保留 |
| 无主动等待任务 | 条件WAIT统计NOT_APPLICABLE |
| 所有节点利用率=0 | CV按声明极限约定为0 |

JSON使用null，CSV使用空值加status/reason；NaN/Infinity禁止进入正式结果。配对主指标任一侧非VALID时整个seed pair无效。

## 11. 聚合总体与权重

同一逐任务账本可被不同聚合方式解释。R-49固定主口径：

```text
cost_per_completed_cpu_hour = Σ completed cost / Σ completed CPU hours
completed_green_coverage = Σ attributed green MWh / Σ task energy MWh
system_green_absorption = Σ green used MWh / Σ green supplied MWh
```

例如两任务成本/CPU小时分别为`1/1`和`9/3`：

```text
正确主值 = (1+9)/(1+3) = 2.5
逐任务比率均值 = (1+3)/2 = 2.0
```

两者回答的问题不同；主成本必须使用前者。

两任务能量1/9MWh、覆盖率100%/0%：

```text
能量加权主覆盖 = 1/(1+9) = 10%
逐任务覆盖均值 = 50%（只作补充）
```

若正式区间2小时，每小时绿电供给10MWh，首小时无任务、次小时使用5MWh：

```text
完整区间系统消纳率 = 5/20 = 25%
只截取有任务时段会错误得到50%
```

统计结论先在每个seed生成一个策略值，再对相同seed做差。若seed A有100条任务差1、seed B有10条任务差-1，正式seed等权配对均值为0；跨seed池化任务会得到约0.818，构成伪重复。任务分位数默认线性插值；资源时间分位数按事件区间持续时间加权；所有方法写入聚合schema和元数据。

## 12. 同一时间戳边界

闭截止要求`t=deadline`仍可启动，因此同刻顺序必须满足：

```text
结束释放/结算
→ 激活既有开始
→ 注入到达与重激活
→ 逐任务提交并激活即时开始
→ 仍未承诺任务到期
→ 批次后快照
```

若先到期后释放，边界任务会被误Expired；若新提交`start=t`要等下一周期才激活，会多记一个周期等待。同刻多个决策的物理elapsed均为0，不能因任务数量重复折扣。R-50和I-19固定了该边界，并要求重复推进同一`t`幂等。

## 13. 尚需用户或pilot冻结的部分

公式量纲和业务选择均已冻结：F-01采用启动SLA，F-02采用`L/1.5L` Flexible，F-03采用固定带宽，F-05采用比例绿电归因，F-06采用线性增量功率和物理计费，S-07采用预注册统计门槛。

`k_soft`、`k_flexible`、`cost_scale`、`absorption_delta_scale`、`gamma_per_second`等仍通过训练pilot冻结，不能用测试集反推；这些数值不改变业务边界。

## 14. 审计结果

本轮发现并修正：

1. 端到端示例未严格对齐1.5秒网格；
2. 网格实现缺少整数tick要求；
3. `reference_cost/reference_marginal_cost`命名不一致；
4. Soft L=0等非法数值缺少边界拒绝；
5. 零分母和空样本缺少NOT_APPLICABLE语义；
6. 绿电零机会的实现指标与候选中性特征未区分；
7. 归一化尺度缺少严格正值约束。
8. 指标核算区间、能量/时间权重、分位数和跨seed聚合顺序未冻结。
9. 闭截止、资源释放、新到达和同刻提交缺少原子事件顺序。

修正后核心手算能够同时满足量纲、边界、守恒和跨文档命名。当前运行代码仍存在追踪矩阵列出的不符合项，本文不能作为实现完成证明。
